# Björn speech experiments

## Current: Björn Bas text-to-speech

The reader now includes **Björn Bas (experimentell)** in Settings → Röst för
uppläsning. It converts new Swedish text to speech using an approximately 6 MB
lexicon and reusable waveform bank. It also supplies read-aloud automatically
when the neural voice pack is absent. The existing playback worker provides
pause/resume, stop, tempo, verse cues and caching.

The bank was prepared offline from 700 words, not complete readings. It contains
2,139 reusable diphone/monophone units and 85 stress/length phoneme variants.
Joins align voiced waveforms by correlation and shorten overlaps when their
pitches differ, avoiding a long blend of incompatible periodic waves. Missing
transitions use monophone halves. The renderer performs no neural inference.

Build and run text-to-WAV without the GUI, ONNX, Python or any external library:

```sh
cmake -S tools/speech/bjorn-poc -B build/bjorn-standalone -DCMAKE_BUILD_TYPE=Release
cmake --build build/bjorn-standalone --target bjorn-say bjorn-compact-tests
build/bjorn-standalone/bjorn-say resources/voices/bjorn-lite-v1 build/new-reading.wav 'Mose såg en stjärna.'
ctest --test-dir build/bjorn-standalone --output-on-failure
```

The root application build also provides `ortho-compact-voice-probe` with the
same arguments. Text can instead be supplied on stdin. The probe reports load,
render and audio duration, diphone backoffs, and words spelled as letters.

Prepare the reusable bank after building the existing neural probes:

```sh
cmake --build build/cmake --target ortho-kokoro-audio-probe
uv run --script tools/speech/bjorn-poc/prepare_voice.py
```

The script greedily selects words for transition coverage and uses the master's
predicted durations to extract waveform units. These alignments are approximate.
`build/bjorn-units/` caches reference PCM and durations with input/model hashes.
The output pack records source revisions, training inputs, gain adjustments and
file hashes. Preparing the default resource folder also updates its entries in
the resource manifest. A prepared pack is committed, so normal builds need no
teacher model, preparation tools or network access for this voice.

The corpus lexicon, shared Swedish number normalization and exact `⟦IPA⟧`
pronunciation overrides work in the native runtime. Unknown words outside the
lexicon are spelled as letter names. Source pitch/duration and limited context
selection can still make delivery uneven; this is an experimental voice needing
listening review. The main app still links ONNX Runtime for Alice/Björn, although
Björn Bas never loads their models. Optional in-app voice downloads are separate
work.

[Current listening comparisons](../../../docs/reports/bjorn-poc-samples/README.md)
contain **reference → first harmonic prototype → Björn Bas from text**. Regenerate:

```sh
python3 tools/speech/bjorn-poc/package_samples.py --compact-probe build/cmake/bin/ortho-compact-voice-probe
```

## Original: complete-utterance harmonic fitting

Fits a small, original native synthesizer to Björn's output. The fitting work
happens offline. Playback needs only the fitted trajectory and a C11 executable
linked to the system C/math library. No eSpeak, GPL speech code, ONNX, NumPy,
Python, or voice model is linked into the renderer.

This is the first **analysis/resynthesis experiment**, not a finished fallback
voice. It reconstructs complete fitted utterances. It cannot yet speak new text
or combine phonemes. The current parameter rate is too large to bundle the
entire Bible as trajectories; its purpose is to establish a sound-quality ceiling
before extracting reusable units or fitting a smaller control model.

[Downloadable lossless comparisons](../../../docs/reports/bjorn-poc-samples/README.md)
are included for listening without running the development server.

## Generate the audition

The existing Björn pack and the two existing Kokoro probes must be prepared and
built first; see [the voice preparation guide](../../../docs/reports/kokoro-voices.md).
Run from the repository root:

```sh
uv run --script tools/speech/bjorn-poc/fit.py
```

The script's inline metadata pins its only analysis dependency, NumPy 2.3.5.
An existing Python 3.12+ environment with NumPy can also run it directly.
The root project's standard-library-only dependency set is unaffected.

Outputs go to `build/bjorn-poc/`:

- `index.html`: audio controls for each reference and the 32/64-harmonic fits.
- `*-reference.wav`: Björn, generated by our existing native probes.
- `*-32.wav`, `*-64.wav`: native reconstructions.
- `*.bjp`: quantized fitted parameters; no PCM samples or model weights.
- `bjorn-render`: the independent native renderer.
- `report.json`: source hashes, teacher pack manifest, compiler, timings, sizes,
  pitch statistics, reconstruction energy and spectral measurements.
- `LICENSE-Kokoro-Swedish.txt`: the teacher pack's original notices.

The probe uses the pack's text front end directly. It does not apply the reader's
separate corpus pronunciation matcher or personal corrections. Pronunciation
mistakes in the reference are therefore also present in the fitted result.

Existing references can be fitted without loading Kokoro:

```sh
uv run --script tools/speech/bjorn-poc/fit.py \
  --reference build/kokoro-audition/bjorn-psalm.wav \
  --output build/bjorn-existing --harmonics 32 64 96
```

References must be mono, signed 16-bit PCM at 24 kHz, at most ten minutes long.
Use `--pack`, `--probes`, `--output`, or `--cc` to select other paths/tools.
Open the generated page in a browser; play each reference and reconstruction.
The script never starts playback automatically.

For remote listening, use the included range-aware server rather than Python's
basic `http.server`: iPhone Safari requests byte ranges when opening audio.

```sh
python3 tools/speech/bjorn-poc/serve.py --directory build/bjorn-poc --port 8766
tailscale serve --bg --http=8766 http://127.0.0.1:8766
```

The HTTP server binds only to loopback. Tailscale supplies the private tailnet
route. Keep the server process running while listening remotely. The included
server tests check Safari's two-byte probe, open/suffix ranges, invalid ranges,
and HEAD responses using only the Python standard library.
Actual iPhone Safari playback still failed over the tailnet after adding range
support; use the downloadable comparisons for review. The HTTP tests establish
the response contract, not working playback on that device.

## Render without the analysis tools

```sh
cc -std=c11 -O2 tools/speech/bjorn-poc/render.c -lm -o build/bjorn-render
build/bjorn-render build/bjorn-poc/psalm-32.bjp build/psalm-reconstructed.wav
```

Or build this directory as its own CMake project:

```sh
cmake -S tools/speech/bjorn-poc -B build/bjorn-render-build -DCMAKE_BUILD_TYPE=Release
cmake --build build/bjorn-render-build
```

The C renderer uses C99 complex arithmetic, supported by Clang and GCC/MinGW.
MSVC's C compiler is not a supported target for this experiment. Only Apple
Silicon execution has been checked so far.

## What is fitted

At a 10 ms hop, the analyzer estimates pitch from a normalized lag-difference
function. It refines each voiced frame's pitch and local pitch slope by
alternating Gauss–Newton steps with weighted least-squares fits of harmonic
amplitudes and phases. Frames span 40 ms. The residual signal supplies energy
targets for sixteen noise bands. Both fits use the same quantized pitch controls
that the renderer consumes.

At playback, oscillator recurrences generate the fitted harmonic waves. An
original inverse FFT shapes deterministic noise to the sixteen band energies.
Overlap-add reconstructs the utterance, with separate energy normalization for
uncorrelated noise. A ring buffer bounds the audio working memory independently
of utterance length; the trajectory itself is loaded into memory.

This uses a more flexible sound model than a small bank of vowel formants:
individual harmonic phases are fitted too. It tests whether a simple waveform
generator can preserve enough of Björn before attempting further simplification.
It does not establish that a much smaller formant-only voice will sound the same.

### BJP2 binary format

All multibyte integers are little endian. A 28-byte header contains `BJP2`, then
six uint32 values: sample rate (24000), exact sample count, hop (240), window
(960), frame count (`ceil(samples/hop)+1`), and harmonic count (1–128).

Each frame holds uint16 pitch in 1/64 Hz (zero means unvoiced), int16 pitch slope
in Hz/s, one uint8 amplitude per harmonic, one uint8 phase per harmonic, and
sixteen uint8 noise-band RMS values. Phase maps one turn to 256 steps. For
amplitudes, zero means silence; 1–255 map uniformly from −96 to 0 dBFS.
The noise band edges in Hz are:
`0 100 200 300 450 650 900 1250 1700 2300 3100 4100 5400 7000 9000 10500 12000`.

32 harmonics use 84 bytes/frame (about 8.4 kB/s); 64 use 148 (14.8 kB/s).
These are uncompressed trajectories, not a competitive speech compression format.
They scale to about 30/53 MB per hour, respectively, in decimal units.

## Verification and interpretation

```sh
uv run --no-project --python 3.12 --with numpy==2.3.5 python -m unittest \
  discover -s tools/speech/bjorn-poc -p '*_test.py' -v
```

Tests check harmonic reconstruction with estimated pitch, chirped phase
recurrences, noise band/energy retention, deterministic output, silence and short
signals, and malformed tracks. Generation also rejects clipping and checks exact
sample counts. Spectral measurements compare short-time magnitude spectra;
they are diagnostic errors, not intelligibility or listening-quality scores.

Listen for vowel identity (especially u/y/ö), consonants, buzzing/hissing, rhythm,
and phrase endings. Matching pitch and timing does not guarantee preserved voice
identity. More harmonics may add little if pitch estimation, transients or the
noise model are the limiting factors. Reusable units, Swedish pitch-accent rules,
arbitrary-text synthesis, playback integration and optional voice downloads are
subsequent work, contingent on the listening result.
